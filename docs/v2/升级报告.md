## 笔记故障根因与修复

1. **编辑已有笔记时依赖未加载的列表缓存。** `edit()` 原先从 `WhileSubscribed` 状态列表查找内容，缓存未加载时可能生成新 ID。现在由 Repository 按 ID 直接读取 DAO，保留原 ID，明确显示加载中和读取错误，找不到内容时不创建替代草稿。
2. **输入回调覆盖最新字段。** 标题和正文回调复制旧的完整表单快照，连续输入可能把另一字段恢复为旧值。现在 `patchNote` / `patchTodo` 对最新草稿逐字段更新，再交给串行保存队列。
3. **重叠水滴可能打开错误内容。** 命中选择曾依赖绘制顺序，现在选择触点最近的水滴中心，导航继续传递该对象 ID。

保存失败会显示错误并保留输入；关闭失败不会清空编辑器。保存和退出先处理键盘与焦点，再等待草稿写入。创建、列表刷新、立即打开、重新进入、已有笔记编辑和强制关闭后的持久化均有回归覆盖。

修复前实际复现了两项失败，保留 [原始失败记录](note-failures-before.txt) 和 [修复后模块测试](notes-fixed-tests.txt)。完整 UI 回归还验证从详情进入编辑器后修改标题、正文仍保留同一 ID。标题单独输入、正文单独输入、多行、特殊字符、长文本、写入失败保留草稿及数据库重开由 `NoteV2DeviceTest` 覆盖。

水滴使用黄金角初始布局、中心弱引力、局部排斥和椭圆软边界。数量变化时区域平滑调整，已有独立拖动布局继续保存；各水滴仍可点击、展开和拖动。

多水滴截图取自性能测试，使用临时测试笔记；测试完成后清理自身创建的数据。采样截图可能包含正在展开的详情，不能作为所有水滴无重叠或持续帧率达标的证明。

实际触摸双击、数据库完成状态、撤销后的水滴恢复及笔记安全通过 `AppDeviceTest` 验证。见 [双击测试](double-tap-tests.txt)、[完成截图](double-completed.png)、[撤销截图](double-undone.png)。首次全面回归出现测试时钟导致的撤销等待失败；修正测试对漂浮页面的时钟推进后，最终 18 项测试全部通过，原失败输出仍保留。

## AI 与 HyperOS 小部件

AI 支持多服务商、Base URL、Key、模型列表、默认模型、切换、连接测试和删除。整个配置用 Android Keystore AES/GCM 加密，放在不参与系统备份的目录。请求有超时、取消、响应大小限制和错误提示。生成笔记、待办或自动识别后必须预览，确认才写入 Room。具体步骤见 [AI 使用说明](AI使用说明.md)。

四个小部件使用标准 RemoteViews：今日概览、快捷添加、待办清单、今日环形进度。待办清单显示 3～5 项、优先级和完成状态，支持完成与撤销；快捷入口打开笔记、待办或 AI 页面。提供深浅色资源与尺寸调整，数据变化后更新，系统定期更新间隔 30 分钟。
