# 真机短时性能记录

本文保留 V1 历史采样。当前 V2 星群采样见 [V2 性能记录](v2/性能记录.md)。

日期：2026-11-15。设备报告型号 2510DRK44C、Android 17 / API 37、HyperOS OS4.0，显示刷新率约 120Hz。构建类型 debug；USB 充电，测试前电量约 46%、电池温度约 31.5°C，最终读取约 32.9°C。电池温度不是 SoC/GPU 温度。

每个场景插入指定数量的临时笔记，开启漂浮/碰撞，关闭减少动态与性能模式，设置显示上限为 60；原有可见条目为 0。预热约 1.5 秒，采集 10 秒，然后清理临时数据和恢复设置。使用 Window.FrameMetrics，按 intended vsync 时间戳去重，记录 TOTAL_DURATION / GPU_DURATION、进程 PSS 和进程 CPU 时间。原始记录：`evidence/performance-final.json`。

| 水滴数 | 去重回调/秒 | 平均帧耗时 ms | P95 ms | GPU 平均 ms | PSS MB | 10 秒内进程 CPU ms |

| 40 | 119.1 | 14.18 | 16.84 | 6.83 | 281.1 | 10367 |

这些是短时绘制回调与帧耗时，**不是 SurfaceFlinger 实际呈现 FPS**。该系统返回约每帧两次 FrameMetrics 回调，最初未去重的回调值约 240/秒，不能解释为 240fps。最终按 vsync 去重。TOTAL_DURATION 包含管线阶段，超出 8.33ms 不可直接换算为实际呈现掉帧；仍说明复杂场景有更高绘制成本。未使用 release 构建、Perfetto 或长时间热稳态采样，不能声称 60 滴稳定达到 120fps。

本次优化包括渐变材质缓存、把位置变化限制到 Canvas 绘制和布局放置、空间分桶碰撞、受控时间步长、后台暂停、减少动态开关。默认上限 40，可选 20/40/60；低性能模式使用 20 滴、约 30Hz 更新和较少粒子；系统热状态达到中度时临时采用低性能模式。

JVM 物理测试覆盖 10/20/40/60 水滴，各 1200 次帧更新，并插入超长帧、选中冲击和同中心重叠。全部坐标有限并受边界约束，拖动归一化坐标可重建。这是数学稳定性测试，不能当作 Android 设备帧率。

待进一步采样：持续拖动/连续扩散与展开/完成消散、混合长文本内容、低性能模式、字体放大、后台返回、GPU/CPU 频率和温度、release 与 Perfetto 对比。当前 debug 的 40/60 滴 P95 超过 120Hz 的单帧预算，后续可继续减少绘制复杂度和跟踪实际呈现掉帧。
